# ことば Translator

Kettu の Vendetta 互換プラグインです。DeepL / OpenAI Responses API / DeepSeek API / Gemini API / OpenRouter に加え、OpenAI Chat Completions・OpenAI Responses・Anthropic Messages 形式のカスタムエンドポイントに対応します。一括翻訳・API 切替・モデルローテーションを組み合わせ、リクエスト件数を抑えます。実行時に外部 npm ライブラリは不要です。

## 導入

1. Kettu のプラグイン追加画面を開きます。
2. `https://porarrirr.github.io/kettu-plugins/kotoba-translator/` を入力してインストールします（末尾 `/` を含む）。
3. プラグインの設定を開き、「設定」でサービスと API キーを入力します。DeepL は API Free / Pro を選択します。OpenAI / DeepSeek / Gemini / OpenRouter は、そのアカウントで利用できるモデル ID も入力してください。JSON 出力と 8,192 出力トークンに対応するテキストモデルが必要です。カスタムエンドポイントはベース URL とモデル ID が必須で、API キーはサービスによっては不要です。
4. 「設定を保存」後、「翻訳」で翻訳先の言語コードと文章を入力します。

配布ファイルは生成済みです。ソース変更後は、このディレクトリで `npm ci`、`npm run check` を実行し、生成された 2 ファイルを更新してください。ビルド時に Babel と esbuild で、iOS Hermes の式評価で非対応の class / async 構文と、ループ内の非同期処理が参照する変数のスコープを変換します。

## 使い方

- 翻訳先を自由入力できます。例: `JA`、`EN-US`、`KO`、`FR`、`zh-Hant`。翻訳元は `auto` で自動検出します。対応言語と地域コードはサービスごとに異なります。LLM も翻訳品質を保証するものではありません。
- 日本語・英語などのボタンからも翻訳先を選べます。「言語設定を保存」でコマンドにも反映します。
- 「一括翻訳」を ON にすると、空行ごとに別の文章として処理します。最大 32 件、各 6,000 文字、入力欄全体は 48,000 文字までです。コードなど空行を含む文章には通常モードを使ってください。
- `/translate text:Hello target:JA` でも翻訳できます。`target` は省略可能です。結果はクリップボードにコピーし、ダイアログは出しません。
- 手動の翻訳画面では結果を確認してからコピーできます。「メッセージの自動翻訳」を ON にすると、表示中の本文を翻訳して置き換えます。翻訳結果の自動投稿はしません。

## 日本語を含む文章は送信しない

ひらがな・カタカナ（半角を含む）・漢字が1文字でもある文章は、翻訳先にかかわらずリクエストを送りません。自動翻訳・コマンド・手動画面・一括翻訳・アドオン説明の翻訳に共通です。日本語を英語などへ訳す操作も送信しません。英語との混在文や、コード・URL内だけに日本語がある場合も原文のままにします。漢字は中国語などと区別できないため、それらの共通漢字を含む文章も対象です。

判定は本文・埋め込みのタイトル・説明・各フィールドなど、翻訳する文字列ごとに行います。一括翻訳は該当する文章だけを除外し、結果の順序は保持します。以前のキャッシュに訳文があっても、日本語を含む原文の置き換えには使いません。

## メッセージ本文の自動翻訳

API キー・モデル・翻訳先を保存し、「メッセージの自動翻訳」を ON にしてください。初期状態は OFF です。Discord のネイティブチャットが通知する可視範囲の本文を、200 ms のスクロール待ちのあと既存の翻訳待ち行列へ送信します。送信直前にも可視範囲・本文・チャンネルを確認し、画面外へ移動した未送信分を待ち行列から取り除きます。すでに送信済みのリクエストは取り消せません。OFF にすると原文へ戻ります。サーバー上のメッセージと MessageStore は編集しません。

翻訳待ち・通信エラー時は原文を表示し、翻訳が届いた本文だけを置き換えます。ダイアログは出しません。編集画面では原文を使い、本文の編集・言語設定の変更・停止後に古い訳文を適用しません。URL のみ、コードのみ、`@everyone`・`@here` のみ、空文、ブロック中・無視中・システムメッセージなどは送信しません。URL だけの投稿（`https://…`・`www.…` のみで本文の文章がないもの）は、リンクプレビューの埋め込みも翻訳せず原文のままにします。埋め込みカードは、ボットなどが作成したリッチな埋め込み（`type: rich`）のタイトル・説明・フィールドだけを置き換えます。Discord が自動生成するリンク・画像・動画のプレビューは本文に文章があっても原文のままです（`type` が取得できない環境では従来どおり翻訳します）。添付画像内の文字と引用プレビューは対象外です。

ON の間は閲覧中の本文が設定済みの外部サービスへ送信されます。自動翻訳には保存済みの設定を使います。モデルや言語を変更したら「設定を保存」を押してください。各メッセージの本文末尾に、本文より小さく薄いネイティブの補足文字で未送信・送信待ち・翻訳中・翻訳済み・エラーを表示します。送信回数はその本文・埋め込み文字列の翻訳リクエストへの参加回数で、一括リクエスト全体の件数とは異なります。保存済みの訳文を使った場合は「キャッシュ」と表示します。「↻ 再翻訳」はそのメッセージだけを再試行し、処理中の重複送信を防ぎます。API の待機時間は守ります。設定画面には全体の送信回数・状態と、表示中のメッセージをまとめて再翻訳する操作もあります。Kettu / Discord の内部描画 API に依存するため、アプリ更新後は互換性の確認が必要です。

## リクエスト統計

設定画面の「統計」タブで、今日・7日間・30日間の送信状況を確認できます。送信回数・成功率・失敗回数・送信文章数・文字数を表示し、プロバイダー別の割合を棒グラフで比較できます。サービスのボタンやグラフを押すと、そのサービスのモデル別内訳に絞り込めます。モデルは送信数順で15件ずつ表示します。画面を開いている間は1秒ごとに表示を更新し、統計表示のための外部通信は行いません。

手動・コマンド・自動本文・アドオン説明の翻訳を共通で集計します。一括送信は文章数によらず1リクエスト、再試行・予備キー・別モデル・別サービスへの切替は実送信ごとに1回です。キャッシュ・重複要求の共用・送信前の取消・日本語による送信抑止・OpenRouterのモデル一覧取得は含めません。成功は訳文の形式・件数・IDまで検証できたリクエストです。HTTPエラー・通信失敗・タイムアウト・不正な訳文は失敗、プラグイン停止中の通信やアプリ終了で結果が残らなかった送信は「中断・結果不明」に数えます。成功率は成功÷（成功＋失敗）で、処理中・中断は分母に含めません。

DeepLはモデル指定なし、OpenRouterはリクエストで指定したモデルIDで集計します。OpenRouter内部の配信先や実課金・トークン使用量は判別しません。文字数はJavaScriptの文字列長（UTF-16）で、再試行時の再送分も含みます。追加前の送信履歴は復元できません。

日付・プロバイダー・モデルID・各件数・文字数だけをプラグイン専用ストレージの `requestStatistics` に保存します。統計には本文・訳文・APIキー・レスポンス本文を保存しません。端末の現地日付で直近30日分、最大3,000組の日付・プロバイダー・モデルを保持し、超過時は古い日付から除外します。再起動・設定変更・翻訳キャッシュ消去・キー削除でも統計は保持されます。「統計をリセット」で全期間の記録を消去し、進行中だった古い結果は戻しません。新たに送ったリクエストから記録を再開します。ストレージ保存に失敗した場合はメモリ内だけで継続します。

## thinking（推論量）

翻訳では速度を優先し、対応する最小の推論量を送ります。Gemini 2.5 Flash / Flash-Lite は `thinkingBudget: 0`、2.5 Pro は最小の128、Gemini 3 Flash・3.5 / 3.6 Flash・Flash-Lite は `thinkingLevel: minimal`、3.8 FlashやPro系は `low` を使います。

DeepSeek は `thinking.type: disabled` と `reasoning_effort: low`、OpenRouter は `reasoning.effort: minimal` を指定します。OpenRouter はモデルが受け付ける最も近いレベルへ変換します。`exclude: true` だけでthinkingを止めた扱いにはしません。OpenAI は対応が分かるモデルについて `none`、`minimal`、`low` などモデル固有の最小値を使います。Pro系の一部では最小値が `medium` / `high` です。古い非推論モデルや対応不明のOpenAI / Geminiモデルには、互換性のため推論設定を追加しません。モデルIDは変更しません。

参照: [Gemini thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking)、[DeepSeek thinking](https://api-docs.deepseek.com/guides/thinking_mode/)、[OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)、[OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning)。

## OpenRouter のモデル一覧

「設定」→「OpenRouter」で OpenRouter 用の API キーを入力し、「OpenRouter のモデル一覧を取得・更新」を押してください。キーがあれば `/api/v1/models/user` でアカウントのプロバイダー・プライバシー・ガードレール設定を反映した一覧を取得します。キー未入力では `/api/v1/models` の公開一覧を取得します。Gemini など他サービスのキーは OpenRouter では利用できません。

テキスト入出力と `response_format` に対応し、既知の出力上限が8,192トークン以上のモデルを表示します。名前・IDでの検索、無料モデルのみの絞り込み、20件単位のページ切替に対応します。「優先モデルにする」または「回転に追加」を選び、最後に「設定を保存」を押してください。IDの手入力も可能です。料金表示は取得時点の USD / 100万トークン単価です。キー未入力の公開一覧は、そのアカウントでの利用可否を保証しません。

一覧は取得ボタンを押したときだけ読み込み、画面を閉じる・キーを変更する・プラグインを停止すると取得を中断します。取得した一覧は保存しません。翻訳は `/api/v1/chat/completions` の JSON モードを使い、`provider.require_parameters` で対応する配信先へルーティングします。自動本文置換・一括翻訳・予備キー・モデル回転・他サービスへの切替は既存の仕組みを共用します。

参照: [モデル一覧API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)、[アカウント設定を反映したモデル一覧](https://openrouter.ai/docs/api/api-reference/models/list-models-filtered-by-user-provider-preferences-privacy-settings-and-guardrails)、[出力形式と配信先の対応](https://openrouter.ai/docs/guides/features/structured-outputs)。

## カスタムエンドポイント

「設定」→「カスタム」で、OpenAI Chat Completions・OpenAI Responses・Anthropic Messages のいずれかの形式で動く任意のエンドポイントを利用できます。OpenAI 互換のローカルサーバー（Ollama、LM Studio、llama.cpp など）、OpenAI 互換プロキシ、Anthropic 互換 API などを登録できます。

1. 「API 形式」で OpenAI Chat / OpenAI Responses / Anthropic Messages を選びます。
2. 「ベース URL」にエンドポイントの元を入力します。末尾の `/` は無視します。
   - OpenAI Chat: 末尾に `/chat/completions` を付けます。すでに `/chat/completions` で終わる URL はそのまま送ります。
   - OpenAI Responses: 末尾に `/responses` を付けます。すでに `/responses` で終わる URL はそのまま送ります。
   - Anthropic Messages: `/v1` で終わる URL には `/messages` を、それ以外には `/v1/messages` を付けます。すでに `/messages` で終わる URL はそのまま送ります。
   - `?key=…` のようなクエリは位置を保ったまま維持します。
3. モデル ID を入力します。API キーは任意で、ローカルサーバーなどキーが不要な場合は空欄にします。
4. 「設定を保存」後、「翻訳」で試します。

認証ヘッダーは OpenAI 形式で `Authorization: Bearer`、Anthropic 形式で `x-api-key` と `anthropic-version: 2023-06-01` です。キー未入力なら認証ヘッダーを送りません。JSON 出力は OpenAI 形式では `response_format` / `text.format` の JSON モード、Anthropic 形式では指示文のみで求めます。JSON モードに対応しないサーバーでは HTTP 400 になることがあります。翻訳の検証（件数・ID・出力打ち切り）は他サービスと共通です。

カスタムには他の LLM サービスと同じ予備キー・モデル回転・API 自動切替・プロバイダー回転を利用でき、統計にも「カスタム」として記録します。回転に参加するにはベース URL とモデル ID の両方が必要です。モデル ID が未知のため推論量の指定は送信しません。出力 8,192 トークン以上のモデルを指定してください。`http://` は暗号化されないため、ローカルネットワークなど信頼できる接続だけに使ってください。

## アドオンブラウザーの説明を翻訳

プラグインを有効にしてから Kettu のアドオンブラウザーを開くと、プラグイン／テーマの各カードの下に「説明を翻訳」が表示されます。「Tap a message to…」のような使い方案内が説明文に含まれていれば、それも翻訳できます。

1. ことば Translator の「設定」で API と翻訳先言語を保存します。
2. アドオンブラウザーの読みたいカードで「説明を翻訳」を押します。
3. 原文の下に訳文が表示されます。「訳文をコピー」「訳文を閉じる」も利用できます。

この操作は保存済みの言語・API・モデル設定を使います。設定保存時は表示済みの訳文をリセットします。API キーがない場合はカード内に設定を促すメッセージを表示します。カードの表示だけで翻訳リクエストは発生しません。複数カードの翻訳は既存の待ち行列・350 ms の集約・キャッシュ・API／モデルローテーションを共用します。

アドオンの情報やインストール操作は元のままです。翻訳するのはカタログの説明文で、説明を編集したり、翻訳を保存したりはしません。Kettu の JSX ランタイムとリストのデータ形式を利用して表示を追加するため、Kettu の更新で動かなくなる可能性があります。ボタンが見つからない場合はプラグインを再読み込みし、アドオンブラウザーを開き直してください。設定画面には表示追加機能の利用可否も示します。

## リクエストを減らす仕組み

表示範囲と翻訳状態に変化がなければ、追加の強制再描画を行いません。保存設定とその識別子を再利用し、埋め込みの置換では各階層のコピーを描画1回につき1度に抑えています。翻訳キャッシュのストレージ保存は、文章ごとではなく一括応答ごとにまとめます。

350 ms 以内に到着した、同じ設定の翻訳をまとめます。API 呼び出しは全体で同時に 1 件、1 回につき最大 8 文章・合計 6,000 文字、処理中を含む翻訳待ちは 32 件までです。例えば短い文章 8 件は 1 リクエスト、10 件は 2 リクエストになります。長文の場合は文字数上限でさらに分割します。

DeepL には `text` 配列を送ります。OpenAI / DeepSeek / Gemini / OpenRouter / カスタムには整数 ID 付き JSON を送ります。OpenAI / DeepSeek は JSON モード、Gemini は `generateContent` の JSON スキーマ付き出力を使用します。カスタムは選択した形式の JSON モード（Anthropic 形式では指示文のみ）を使います。返答の件数・ID・重複・空の訳文・出力打ち切りを検証し、ID 順に元の文章へ対応付けます。壊れた JSON を自動で修復・再送してリクエストを増やす処理はありません。LLM への指示では、改行・Markdown・URL・メンション・絵文字・コードブロックに加えてスポイラー記号（`||…||`）の保持を明示的に求め、ネタバレ表示が外れないようにしています。

同じ文章・設定の処理中リクエストは共用し、成功した訳文はメモリに加えて Kettu のプラグインストレージへ最大100件・30日間保存し、再起動後も再利用します。保存量は原文・設定識別子・訳文の合計40万文字以内です。API キーは保存キャッシュの識別子に含めません。翻訳先・翻訳元・モデルなどが異なる結果は使いません。

「設定」内の「翻訳キャッシュを消去」で、保存済みとメモリ内のキャッシュをまとめて消去できます。処理中だった古い応答はキャッシュへ戻しません。自動翻訳 ON の間は、現在表示中の対象を改めて翻訳します。設定保存やプラグイン停止だけでは保存キャッシュを消しません。原文・訳文は端末のプラグインストレージに保存されます。

## API・プロバイダー・モデルのローテーション

各サービスに主キー 1 個と予備キー 3 個まで登録できます。LLM サービスは優先モデル 1 個と追加モデルを登録できます。Gemini は追加モデル数に上限がありません。OpenAI / DeepSeek / OpenRouter / カスタムは追加モデル 3 個までです。追加モデル ID は改行またはカンマで区切ります。Gemini の ID は `models/` 接頭辞の有無をどちらも受け付けます。

「API 自動切替」と「モデルローテーション」は独立した設定で、初期状態は両方 ON です。API 切替 OFF でもモデル回転を利用でき、モデル回転 OFF でも予備キー・他サービスへの切替を利用できます。モデルはキーごとに順番に使い、呼び出すたびに次のモデルへ進みます。対応していないモデルを自動で選ぶことはありません。切替先のキーとモデルをあらかじめ登録して保存してください。

「プロバイダーローテーション」を ON にして「設定を保存」を押すと、成功時もリクエストごとに次の設定済みサービスへ進みます。初期状態は OFF で、既存の設定は保持します。選択中サービスから開始し、その後は DeepL → OpenAI → DeepSeek → Gemini → OpenRouter → カスタムの順で未選択のサービスを巡回します。キー未設定（カスタムはベース URL かモデル未設定）、または LLM の優先モデル未設定のサービスは対象外です。選択中サービスのキー・優先モデルは従来どおり必要です。

API 自動切替・プロバイダー回転・モデル回転は独立した設定です。プロバイダー回転 ON なら API 自動切替 OFF でも各サービスの主キーを巡回します。予備キーは API 自動切替 ON の場合だけ使います。各サービス内のモデル回転も併用できます。待機中・利用不可の候補は避け、全候補が待機中なら最も早く使える候補を待ちます。実際の送信（失敗を含む）で次のプロバイダーへ進み、キャッシュ利用・重複要求の共用・送信前の取消では順番を進めません。一括翻訳は文章単位でなくリクエスト単位で巡回します。巡回位置はメモリ内のみで、プラグイン再読み込み時にリセットします。

以下はプロバイダー回転 OFF の優先順です。ON の場合は上記の巡回順を優先し、同じ間隔・クールダウン・再試行上限を適用します。

1. 選択中サービスの主キー、予備キー、他サービス（DeepL → OpenAI → DeepSeek → Gemini → OpenRouter → カスタムのうち未選択のもの）の順で、待機していないキーとモデルを選びます。失敗後は、すぐ送れる別サービスを同じサービスの別モデルより優先します。別サービスが待機中で同じサービスの別モデルが送信可能なら、それを使います。すべて待機中なら最も早く利用できる組み合わせを待ちます。
2. プロバイダー＋キーごとに呼び出し間隔を管理します。通常は 3 秒、設定範囲は 1〜60 秒です。成功後はモデルを変えても通常間隔を守ります。失敗後の別候補への切替では、このプラグインが設ける同じキーの間隔を送信開始時刻間で最低1秒へ短縮します。使える別サービス・予備キーなら追加の間隔待ちはありません。サーバー指定の待機とモデルのクールダウンは短縮しません。
3. HTTP 408 / 429 または 5xx（529 を含む）では、そのプロバイダー＋キー＋モデルをクールダウンし、別の利用可能なモデル／キー／サービスに一括データをそのまま切り替えます。画面にはサービス名・キー番号・モデル ID・検知した HTTP ステータスを表示します。DeepL はモデルの指定がないため、キー単位でクールダウンします。
4. 待機時間は `Retry-After`（秒数・HTTP 日付）、Gemini の `google.rpc.RetryInfo`、指数バックオフ＋ランダム待機の最大値です。最短待機が 120 秒を超える場合はエラーで止まり、クールダウンは保持します。
5. 401 / 403（認証・権限）や 402 / 456（残高・利用枠）のキーは、設定の再保存または再起動まで除外します。LLM の 400 / 404 / 422 は該当キー＋モデルだけを除外し、他のモデルは利用可能なままにします。通信失敗・タイムアウトでは、その組み合わせを同じバッチで再送せず、別の候補へ切り替えます。複数候補を設定している場合、最後の候補を含め1回の応答待ちは5秒です。候補を1つだけ設定した場合は60秒です。Gemini の429 / 5xxとOpenRouterの402だけ、待機情報のためエラー本文を最大100ms読みます。その他のHTTPエラーは本文を待たずに判定します。取得済みの `Retry-After` と読み取れた Gemini `RetryInfo` は守ります。OpenRouterがHTTP 200の本文内に返したエラーもコード・種別で判定し、失敗として切り替えます。OpenRouterの一時的な同時処理予算不足（`openrouter_in_flight_budget` と `Retry-After` 付き402）はキーを永久除外せず、同じキーの全モデルに待機を適用します。翻訳形式・件数・ID不正や出力打ち切りは、その組み合わせを同じバッチで再送せず、別候補があれば切り替えます。未検証の訳文は表示・保存しません。その他の4xxは終了します。
6. 1 バッチにつき最大 12 回です。複数候補がある場合、同じキー＋モデルは1回だけ試し、429 / 5xx の候補を同じバッチで再試行しません。候補が1つの場合だけ最大4回まで再試行します。利用可能な組み合わせがなくなれば停止します。API 切替とプロバイダー回転が両方 OFF では選択中サービスの主キーだけ、モデル回転 OFF では優先モデルだけを利用します。

他サービスへの切替時は、翻訳する文章をそのサービスにも送信します。キーはマスク表示しますが、保存先は Kettu のプラグインストレージであり、Keychain 等の暗号化保管ではありません。設定からすべての主キー・予備キーを削除できます。削除時は実行中リクエストを中断しますが、送信済みデータをサービスから撤回するものではありません。

同じ契約に属する複数キーは、レート制限や利用枠を共有する場合があります。特に [Gemini の制限はプロジェクト単位](https://ai.google.dev/gemini-api/docs/rate-limits)で、モデルごとにも異なります。プラグインはキーが属するプロジェクトを判別できないため、共有枠の状態までは同期できません。キーやモデルを増やしても契約上限が増えるとは限りません。一括送信はリクエスト件数を減らしますが、文字数・トークンの利用枠や料金は消費します。制限状態はメモリ内で管理するため、Discord の再起動やプラグインの再読み込みでリセットされます。

## ビルド・検証

Node.js 22 以上を使用します。このディレクトリで実行してください。

```sh
npm ci
npm run check
```

ソース・回帰テスト・配布物はこのディレクトリで完結しています。`index.js` を直接編集せず、`src/` を編集してビルドしてください。Babel と esbuild による Hermes 向け構文変換を維持しています。テストは通信をモックし、配布式の評価・ハッシュ・応答順・停止・設定変更・キャッシュ・API 切替などを確認します。

過去に Gemini の実通信と Kettu 上の翻訳表示を確認していますが、この公開用構成では実 API・実機で再検証していません。カスタムエンドポイントの実通信、各サービスの全モデル、アプリ更新後の内部 API 互換性は未確認です。
